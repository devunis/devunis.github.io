RAG는 외부 자료를 검색해 답변 생성에 사용하는 구성 방식입니다. 벡터 검색은 가능한 검색 수단 중 하나이며, 키워드·하이브리드 검색도 사용할 수 있습니다.

## 🔎 구성 요소

검색했다고 답변의 사실성이 자동 보장되지는 않습니다. 원문 최신성, 사용자 권한, 정답 문서 포함 여부, 생성된 답변의 근거를 확인해야 합니다.

## 📊 검색 구성 비교

| 대상 | 구분 | 검토할 기능 |
| --- | --- | --- |
| FAISS | 벡터 검색 라이브러리 | 인덱스·거리 함수·CPU/GPU, 별도 메타데이터 관리 |
| Qdrant | 벡터 DB | 벡터·payload, 필터·배포·복제 구성 |
| Chroma | 문서·임베딩 저장·검색 | 개발 인터페이스, 로컬·서버·클라우드 구성 |
| Milvus | 벡터 DB | 인덱스 선택, 배포·확장·운영 구성 |

FAISS를 독립 DB 서버와 같은 제품으로 분류하지 않습니다. 규모 하나만으로 제품을 나누거나 특정 제품에 고정된 정확도·응답 시간을 부여할 수 없습니다.

## 🧪 비교 실험을 설계하기

같은 문서·질의·임베딩·거리 함수·필터·검색 수로 비교합니다. 인덱스별 검색 품질과 지연을 함께 보고, 업데이트·삭제·복구·권한 처리까지 검증합니다.

과거 글의 정확도 비교표는 실제 측정 근거가 없어 제거했습니다. reranker와 청킹까지 서로 다르게 설정한 결과로 DB 자체의 우열을 판단해서도 안 됩니다.

## ✅ 선택 기준

기존 운영 환경, 메타데이터 필터, 동시 요청, 데이터 갱신과 비용을 먼저 정합니다. 실제 자료로 검색 실패를 분석한 뒤 필요한 구성을 선택합니다.
