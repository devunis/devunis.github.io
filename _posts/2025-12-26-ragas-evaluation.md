Ragas는 RAG 등 LLM 애플리케이션의 평가를 돕는 프레임워크입니다. 자동 평가 결과도 선택한 평가자·모델·데이터·지표 정의의 영향을 받으므로 객관적 정답의 보증으로 해석하면 안 됩니다.

## 📊 무엇을 나눠 평가할까?

| 평가 관점 | 확인할 질문 |
| --- | --- |
| 검색 재현 | 답변에 필요한 자료를 가져왔는가? |
| 검색 관련성·순서 | 무관한 문서가 상위에 많은가? |
| 답변 근거 | 답변의 주장이 검색 문맥으로 뒷받침되는가? |
| 답변 관련성 | 사용자의 질문에 대응하는가? |
| 정확성 | 신뢰할 수 있는 정답·검토 기준에 맞는가? |

Faithfulness가 높아도 원문이 틀렸거나 오래되면 답변이 사실과 다를 수 있습니다. 검색의 Recall@K와 답변 품질 역시 다른 지표입니다.

## 🗂️ 평가 데이터 만들기

질문, 검색 문맥, 생성 답변, 필요한 경우 기준 답변·정답 문서 ID를 저장합니다. 데이터가 요구하는 입력은 선택한 지표와 버전에 따라 다릅니다. 개인정보·권한 정보와 원문의 버전도 관리합니다.

튜닝 데이터와 최종 평가 데이터를 분리하고, 자주 묻는 질문뿐 아니라 모호한 질문·정답 없는 질문·권한 제한 사례를 포함합니다. 모든 서비스에 같은 최소 문항 수가 충분한 것은 아닙니다.

## 🧪 비교 절차

1. 지표 정의와 평가자·모델·프롬프트 버전을 고정합니다.
2. 같은 질문으로 기준 구성과 변경 구성을 실행합니다.
3. 평균 외에도 질문 유형별 결과와 실패 사례를 확인합니다.
4. 자동 판정의 일부를 사람이 검토해 오판을 찾습니다.
5. 품질과 응답 지연·비용을 함께 기록합니다.

Ragas의 API·클래스·입력 형식은 버전에 따라 달라질 수 있어 설치 버전에 맞는 공식 예제로 시작합니다. 이 글에서는 실행하지 않은 출력 점수나 SenPick의 실제 결과를 제시하지 않습니다.

## ✅ 점수를 해석할 때

보편적인 합격 점수표 대신 업무 위험과 검토 결과로 기준을 정합니다. 자동 오프라인 평가와 실제 사용자를 무작위 배정하는 온라인 A/B 테스트는 다른 실험입니다. 통계와 표본을 검토하지 않고 한 번의 점수 차이를 개선으로 확정하지 않습니다.
