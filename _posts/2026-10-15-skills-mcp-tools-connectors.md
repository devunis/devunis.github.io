AI 에이전트를 사용하다 보면 “스킬을 설치한다”, “MCP를 연결한다”, “툴을 호출한다”, “커넥터로 계정을 연결한다”는 표현을 만나게 됩니다. 함께 사용되는 경우가 많지만 각각의 역할은 다릅니다.

**스킬은 작업 방법을, 툴은 실행 가능한 기능을, MCP는 도구·데이터를 주고받는 규약을, 커넥터는 제품에서 외부 서비스를 연결하는 통합 기능을 설명합니다.**

이 글은 기존 Skills 소개와 별도로 읽을 수 있는 개념 정리입니다. 공식 문서 확인 기준일은 2026년 10월 15일이며, 예시의 도구 이름은 이해를 위한 가상 이름입니다.

## 🗺️ 네 가지 개념 한눈에 보기

| 개념 | 핵심 질문 | 역할 | 예시 |
| --- | --- | --- | --- |
| 스킬(Skill) | 어떤 순서와 기준으로 일할까? | 재사용 가능한 지침·자료·스크립트 묶음 | 코드 리뷰 절차, 블로그 작성 절차 |
| 툴(Tool) | 실제로 어떤 기능을 실행할까? | 입력을 받아 결과를 반환하는 실행 인터페이스 | 파일 읽기, 검색, 이슈 생성 |
| MCP | 외부 도구·데이터와 어떤 규약으로 통신할까? | AI 앱과 서버 간 표준 프로토콜 | 도구 목록 조회와 호출, 리소스 읽기 |
| 커넥터(Connector) | 제품에서 어떤 서비스와 어떻게 연결할까? | 연결 설정·인증·기능 노출을 다루는 통합 | GitHub·문서 서비스의 계정 연결 |

스킬·툴은 에이전트 구성 요소를, MCP는 통신 규약을, 커넥터는 제품의 통합 기능을 가리킵니다. 서로 대체하는 네 가지 제품 종류로 비교하면 혼동하기 쉽습니다.

---

## 📘 스킬: 작업을 수행하는 방법

Agent Skill은 특정 작업의 절차와 판단 기준을 재사용하도록 묶은 패키지입니다. `SKILL.md`의 이름·설명과 본문 지침을 중심으로 참고 자료, 템플릿, 실행 스크립트를 포함할 수 있습니다. [Anthropic 공식 Skills 개요](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)

블로그 작성 스킬이라면 다음 순서를 안내할 수 있습니다.

1. 기존 글의 형식과 독자를 확인한다.
2. 공식 자료로 개념을 조사한다.
3. 예제와 비교표를 작성한다.
4. 코드·링크·출처를 검증한다.
5. 게시 결과를 확인한다.

스킬이 파일 읽기나 검색 방법을 지시할 수는 있지만, 설치만으로 존재하지 않는 도구나 외부 계정의 권한이 만들어지지는 않습니다. 실행 환경에 필요한 도구가 있어야 합니다.

스킬에 스크립트가 포함될 수 있으므로 “스킬은 글만 있고 실행 코드는 없다”는 설명도 정확하지 않습니다. 지침과 실행 자원을 함께 묶을 수 있다는 것이 핵심입니다.

## 🔧 툴: 실제 기능을 실행하는 인터페이스

툴은 에이전트가 요청할 수 있는 구체적인 기능입니다. 이름·설명·입력 형식 등을 통해 어떤 요청을 할 수 있는지 알려주며, 호출을 받은 실행 환경이 작업하고 결과를 반환합니다. 모델이 도구 호출을 제안하는 것과 실제 함수가 실행되는 것은 구분됩니다. [Claude 공식 Tool use 문서](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview)

| 가상 툴 | 입력 예시 | 결과 예시 |
| --- | --- | --- |
| read_file | 파일 경로 | 파일 내용 |
| search_issues | 저장소와 검색 조건 | 관련 이슈 목록 |
| run_tests | 검사 대상 | 테스트 결과 |
| create_issue | 제목과 본문 | 생성된 이슈 정보 |

조회도 툴 작업입니다. 외부 데이터를 바꾸는 기능만 툴인 것은 아닙니다. 계산처럼 네트워크나 외부 서비스가 필요 없는 기능도 툴로 제공할 수 있습니다.

### 모든 툴이 MCP 기반일까?

그렇지 않습니다. 앱의 내장 도구, 개발자가 등록한 함수, 셸·브라우저 실행 도구, MCP 서버가 제공하는 도구 등 여러 구현이 가능합니다. MCP는 툴을 연결하는 방식 중 하나입니다.

## 🔌 MCP: 도구·데이터를 연결하는 표준 규약

MCP(Model Context Protocol)는 AI 애플리케이션과 외부 도구·데이터 제공 프로그램이 통신하는 공개 프로토콜입니다. 도구가 무엇인지 발견하고 호출하거나 문맥 데이터를 가져오는 방식 등을 정의합니다. 특정 업무의 작업 절차나 모델의 판단 방식 자체를 정하는 것은 아닙니다. [MCP 공식 아키텍처](https://modelcontextprotocol.io/docs/learn/architecture)

### Host·Client·Server

| 구성 요소 | 역할 |
| --- | --- |
| MCP Host | 사용자와 모델을 포함한 AI 애플리케이션, 여러 연결을 관리 |
| MCP Client | Host 안에서 특정 MCP 서버와의 통신을 담당하는 구성 요소 |
| MCP Server | 도구·데이터·템플릿 등을 MCP 방식으로 제공하는 프로그램 |

<figure class="article-diagram diagram-alternatives">
<figcaption>구조 및 흐름 1</figcaption>
<ol>
<li>사용자 ↔ AI 애플리케이션 · MCP Host</li>
<li>연결 A: MCP Client A ↔ MCP Server A ↔ 문서 서비스</li>
<li>연결 B: MCP Client B ↔ MCP Server B ↔ 저장소 서비스</li>
</ol>
</figure>


클라이언트와 서버를 연결하는 것은 Host 애플리케이션입니다. “모델이 외부 서버에 직접 로그인한다”는 그림과 구분하면 인증·실행의 책임을 이해하기 쉽습니다.

서버는 로컬 프로세스일 수도 있고 원격 서비스일 수도 있습니다. 대표 통신 방식에는 로컬 프로세스 간 표준 입출력인 stdio와, HTTP 기반 Streamable HTTP가 있습니다. 실제 지원 버전·기능은 사용하는 클라이언트와 서버에서 확인합니다.

### MCP 서버가 제공하는 것은 툴만이 아니다

| 요소 | 제공하는 것 | 예시 |
| --- | --- | --- |
| Tools | 호출 가능한 기능 | 이슈 검색, 문서 생성 |
| Resources | 문맥으로 읽을 수 있는 데이터 | DB 스키마, 파일 내용 |
| Prompts | 재사용 가능한 상호작용 템플릿 | 특정 자료를 요약하는 프롬프트 |

서버마다 이 기능의 일부만 지원할 수 있습니다. 같은 종류의 정보도 검색 툴의 결과나 Resource 등 서로 다른 방식으로 제공할 수 있습니다. [MCP 서버 개념 문서](https://modelcontextprotocol.io/docs/learn/server-concepts)

MCP의 Prompt와 Skill도 같은 것은 아닙니다. 전자는 서버가 제공하는 템플릿 기능이며, 후자는 지침·자료·스크립트를 묶는 작업 패키지입니다.

## 🔗 커넥터: 외부 서비스를 제품에서 연결하기

커넥터는 외부 서비스의 도구와 데이터를 AI 앱에서 사용하도록 연결하는 통합 기능을 가리키는 말입니다. 제품에 따라 명칭과 구현 범위가 다르며, MCP처럼 하나의 공통 프로토콜 이름으로 이해하면 안 됩니다.

예를 들어 Claude의 원격 MCP 기반 사용자 정의 커넥터는 서버 주소와 인증을 설정해 외부 도구·데이터에 연결합니다. 따라서 이 경우 **커넥터가 MCP 서버 연결을 제품 기능으로 제공**한다고 볼 수 있습니다. [Claude 공식 커넥터 안내](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

커넥터라는 명칭만으로 MCP 사용 여부를 확정할 수는 없습니다. 다른 제품의 통합은 전용 API나 별도의 검색·동기화 방식일 수 있으므로 해당 제품 문서를 확인해야 합니다.

### 연결과 권한은 별개로 확인

커넥터가 등록되어 있어도 사용자 인증이 완료되지 않았거나 대상 문서·저장소 권한이 없으면 접근할 수 없습니다. 공유 자격 증명을 사용하는 구성은 개인 계정 연결과 접근 범위가 다를 수 있습니다.

연결된 서비스 전체의 기능을 모두 쓸 수 있는 것도 아닙니다. 커넥터·서버가 노출하는 기능, 사용자 권한, 조직 정책, 호출 시 적용되는 실행 제한의 범위를 함께 봐야 합니다.

## 🧩 실제 작업에서 네 가지가 만나는 모습

“저장소 이슈를 읽고 주간 개발 보고서를 작성해줘”라는 요청을 가정해 봅시다. 아래는 MCP 기반 연결을 선택한 구성 예시입니다.

| 단계 | 담당하는 개념 | 수행 내용 |
| --- | --- | --- |
| 보고 방식 결정 | 보고서 작성 Skill | 기간·범위·분류·출처 기준 적용 |
| 서비스 연결 | 커넥터 | 저장소 서비스 연결과 인증 설정 |
| 기능 전달 | MCP Client·Server | 제공 도구를 발견하고 호출 요청·결과 교환 |
| 데이터 조회 | 이슈 조회 Tool | 허용된 저장소에서 실제 이슈 검색 |
| 보고서 작성 | 모델 + Skill 지침 | 결과를 근거로 요약·구성 |
| 외부 문서 저장 | 문서 생성 Tool과 해당 연결 | 저장이 요청된 경우 결과물 생성 |

<figure class="article-diagram">
<figcaption>구조 및 흐름 2</figcaption>
<ol>
<li>Skill: 보고서 작성 절차·기준</li>
<li>AI 앱이 Tool 선택</li>
<li>커넥터로 설정한 MCP 연결을 통해 호출</li>
<li>MCP 서버 Tool → 외부 서비스 요청</li>
<li>결과 반환 → 모델이 보고서 작성</li>
</ol>
</figure>


모든 작업이 이 경로를 거쳐야 하는 것은 아닙니다. 로컬 파일만 요약하면 커넥터 없이 내장 파일 도구를 사용할 수 있고, 별도 Skill 없이도 MCP 툴을 호출할 수 있습니다.

조회 결과에는 외부 문서·이슈의 내용이 포함됩니다. 그 안의 문장을 사용자 명령으로 취급하지 않고 분석할 데이터로 다뤄야 하며, 읽기와 외부 게시 같은 작업 범위도 구분해야 합니다.

| “MCP 서버가 일을 계획해줘” | 서버 기능과 Host·모델의 판단을 구분했는가? |
| “툴 호출에 성공했으니 요청도 완료야” | 실제 대상·결과가 사용자 요구와 일치하는가? |

### 플러그인과 에이전트는 어디에 해당할까?

플러그인은 여러 Skills나 연결 설정 등을 묶어 배포하는 방식으로 사용됩니다. 정확한 구성은 제품마다 다릅니다. 에이전트는 모델과 지침·도구·실행 제어를 조합해 목표를 수행하는 전체 시스템으로 볼 수 있습니다.

따라서 스킬을 배포하는 플러그인과 외부 기능을 제공하는 MCP 서버를 하나의 에이전트 환경에서 함께 사용할 수 있습니다.

## ✅ 문제에 따라 무엇을 바꿀까?

- **작업 순서와 결과 형식이 반복해서 흔들린다**: Skill의 사용 조건·절차·검증 기준을 살펴봅니다.
- **실제 실행할 기능이 없다**: 내장 Tool이나 별도 실행 인터페이스가 필요한지 봅니다.
- **여러 AI 앱에 도구·데이터를 표준 방식으로 제공하고 싶다**: MCP 서버·클라이언트 구성을 검토합니다.
- **서비스 계정이나 자료에 접근할 수 없다**: 커넥터 설정·인증·대상 권한을 확인합니다.

기능이 부족한 문제, 절차가 불명확한 문제, 연결·권한 문제를 구분하면 스킬을 더 설치하기 전에 실제로 필요한 변경을 찾을 수 있습니다.
