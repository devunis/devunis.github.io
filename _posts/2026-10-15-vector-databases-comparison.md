> 데이터베이스 종류와 대표 제품을 비교하는 7편 시리즈의 6편입니다. 각 제품명은 공식 소개 또는 문서로 연결됩니다.

“비밀번호를 잊었어요”라는 질문으로 “계정 접근 복구 방법” 문서를 찾으려면 단어의 일치만으로는 부족할 수 있습니다. 벡터 검색은 텍스트·이미지 등을 임베딩으로 표현하고 유사도를 기준으로 후보를 찾습니다.

이 글에서는 대표 벡터 제품 5개와 PostgreSQL 확장인 pgvector를 비교합니다.

---

## 🧠 벡터 DB는 무엇을 저장할까?

보통 벡터와 문서 ID, 출처, 권한·카테고리 같은 메타데이터를 함께 다룹니다. 임베딩은 별도 모델이 생성하거나 제품이 제공하는 모델 연계를 사용할 수 있습니다. 벡터 DB가 그 자체로 언어의 의미를 만들어 내는 것은 아닙니다.

기본 흐름은 다음과 같습니다.

```text
원문 → 청크 분할 → 임베딩 생성 → 벡터·메타데이터 저장
질문 → 같은 체계의 임베딩 생성 → 유사도 검색 → 권한·조건 확인 → 답변 생성
```

모델과 벡터 차원, 거리 함수를 일관되게 관리해야 합니다. 모델을 바꾸면 기존 벡터의 재생성과 인덱스 갱신이 필요할 수 있습니다. [Qdrant 개요](https://qdrant.tech/documentation/overview/)

## 🐘 pgvector는 별도 DB가 아닌 PostgreSQL 확장

[pgvector](https://github.com/pgvector/pgvector)는 PostgreSQL에 벡터 저장과 유사도 검색 기능을 추가합니다. 기존 테이블·SQL·트랜잭션과 함께 벡터를 다룰 수 있으며, 정확 검색과 HNSW·IVFFlat 인덱스를 제공합니다.

| 비교 기준 | PostgreSQL + pgvector | 전용 벡터 DB |
| --- | --- | --- |
| 기존 업무 데이터와 결합 | SQL·조인·트랜잭션 활용 | 외부 데이터 연계와 동기화 검토 |
| 운영 구성 | 기존 PostgreSQL에 기능 추가 가능 | 별도 서비스 또는 관리형 도입 |
| 확장·검색 기능 | PostgreSQL·확장·배포 구성의 범위 | 제품별 샤딩·검색·관리 기능의 범위 |
| 선택 시 검증 | 업무 쿼리와 검색의 자원 경쟁 | 필터·검색·업데이트·복구 특성 |

pgvector는 “작을 때만”, 전용 제품은 “클 때만”이라고 단정하지 않습니다. 데이터량, 필터 선택도, 업데이트 빈도, 동시 요청, 검색 품질 목표를 같은 조건에서 측정해야 합니다.

Elasticsearch·OpenSearch·Redis 등 다른 계열에도 벡터 기능이 있습니다. 벡터 검색 기능과 독립적인 벡터 DB 제품은 구분해서 비교합니다.

## 🎯 벡터 DB 선택에서 중요한 지표

### 1. 검색 품질과 지연

근사 최근접 이웃 검색(ANN)은 검색 속도와 정확도 사이의 절충이 있습니다. 인덱스와 탐색 설정을 조정할 때 Recall@K 같은 지표와 응답 지연을 함께 봐야 합니다. 제품 이름만으로 결과 품질을 판단할 수는 없습니다.

### 2. 필터와 권한

“이 사용자에게 공개된 문서 중 가장 유사한 10개”가 실제 요구일 수 있습니다. 유사한 문서를 먼저 고른 뒤 권한 없는 결과를 제거하면 결과가 부족해질 수 있습니다. 제품의 필터 적용 방식과 실제 데이터 분포를 검증해야 합니다.

### 3. 키워드와 벡터의 결합

제품 코드, 정확한 오류 메시지, 고유명사는 키워드 검색이 유리할 수 있습니다. 의미 검색과 키워드 검색을 결합한 하이브리드 검색, 후보를 다시 평가하는 리랭킹을 비교할 수 있습니다.

### 4. 갱신·삭제·복구

벡터 추가 속도만 보지 말고 문서 수정, 삭제 반영, 인덱스 재구축, 백업과 복구도 확인해야 합니다. 검색 결과에는 원문 출처와 버전을 연결해 두는 것이 좋습니다.

## ✅ 먼저 무엇을 검증할까?

1. 실제 질문과 정답 문서로 평가 데이터를 만듭니다.
2. 같은 임베딩·거리 함수·검색 수로 후보 제품을 비교합니다.
3. 실제 권한·필터 조건과 업데이트를 포함합니다.
4. 품질, 지연, 비용, 운영 부담을 함께 평가합니다.

RAG 품질은 DB 외에도 청킹, 임베딩, 검색 전략, 리랭킹, 답변 모델에 영향을 받습니다. DB를 바꾸기 전에 어느 단계에서 정답 문서를 놓치는지 확인해야 합니다.
